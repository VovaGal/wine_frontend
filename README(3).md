# Сканер этикеток «Своё вино»

React + TypeScript + Vite

## Запуск

```bash
npm install
cp .env.example .env
npm run dev
```

`npm run build` проверяет TypeScript и собирает `dist/`.

Для просмотра без backend задайте `VITE_DEMO_MODE=true` в `.env` и **перезапустите Vite**. Демо читает три карточки «Прибой Марченко» и запись №6 «Фиолетовый Ранний петнат» из `public/demo/wines.json`. Значения `rating` и `roskachestvo` не выдумываются. Если расширение изображения вин иное, поправьте `image_url` в JSON. Без картинки показывается стилизованная бутылка.

Выберите в сканере изображение с одним из следующих имён и подтвердите кадр. В демо **содержимое фото не распознаётся**: сценарий определяется по имени файла.

| Имя выбранного фото | Сценарий |
| --- | --- |
| `wine_1.webp`, `wine_2.webp`, `wine_3.webp` | карточка соответствующего вина |
| `wine_4.webp` | три возможных вина с изображениями в циклической карусели |
| `wine_5.webp` | форма для вина, которого нет в базе |
| `wine_6.webp` | карточка вина №6; после закрытия — демонстрационное приглашение на фестиваль |

Для сценариев 4 и 5 достаточно фото с этими именами: отдельные записи в каталоге не нужны. Для сценария 6 требуются и фото `wine_6.webp`, и запись №6 в `wines.json`. Сценарии 4 и 5 показывают соответственно первые три карточки или пустую форму. У приглашения 6-го вина статус демонстрационного: участие конкретной бутылки в фестивале **не подтверждается**. После проверки интерфейса верните `VITE_DEMO_MODE=false`. Подробнее: `public/demo/README.md`.

По умолчанию Vite проксирует `/recognition` на `http://127.0.0.1:8000`. Для удалённого сервера укажите `VITE_API_BASE_URL=https://...` и включите CORS для origin frontend на сервере либо настройте reverse proxy.

Если FastAPI включает router под `/api/v1`, задайте `VITE_API_BASE_URL=/api/v1` и настройте соответствующий proxy в `vite.config.ts`. Путь и CORS зависят от основного приложения backend, которого нет в прикреплённом файле маршрутов.

**Камера** через `getUserMedia` доступна на телефоне только в HTTPS-контексте (либо на `localhost`). Без неё остаётся выбор фотографии и системная камера через файловый input. Фото из галереи можно масштабировать ползунком или жестом двух пальцев и двигать пальцем либо ползунками. Область рамки вырезается, уменьшается до 1440 px и отправляется как JPEG. Демо не содержит ключей MinIO: в рабочем режиме загрузка идёт через FastAPI.

На главной странице используются SVG `public/brand/svoe-vino-logo.svg`, `public/brand/rshb-logo.svg` и `public/brand/eighteen-plus.svg`, взятые с сайта `https://vino-svoe.ru/`. Изображение сомелье Григория находится в `src/assets/grigory.jpg`; карточка пока только анонс.

## Подключённый API

- `POST /recognition/tasks` с `multipart/form-data` и полем `image` возвращает `task_id`, `status`, `uploaded_image_id`, `status_url`.
- `GET /recognition/tasks/{task_id}` опрашивается раз в секунду до `completed`, `failed` или таймаута 30 секунд. ID задачи хранится в `sessionStorage`, поэтому страницу можно обновить и продолжить ожидание.
- `POST /recognition/tasks/{task_id}/confirm` предназначен для worker и не вызывается браузером.

Отдельный endpoint с плоским ответом `{"slug":"..."}` для оценочного Bash-скрипта из ТЗ должен реализовываться в backend. Данный браузерный интерфейс его не заменяет.

Успешный ответ текущего backend содержит `wine` или `similar_wines`. `similar_wines` возвращаются при неудачном поиске карточки по slug; это **не** top-3 уверенных предсказаний модели. Компонент подписывает их «Похожие вина в каталоге». Когда появятся поля `decision` и `candidates`, интерфейс покажет вариант «Возможно, вы искали...» с тремя кандидатами модели. При уверенном совпадении карточка вина открывается сразу.

## Что пока ожидает backend

| Возможность | Ожидаемое поле или endpoint | Поведение до интеграции |
| --- | --- | --- |
| Уверенность и top-3 | `decision`, `candidates: [{wine, match_score, confidence, description}]`; при наличии `confidence` это должна быть калиброванная величина от 0 до 1 | существующий `wine` открывается, `similar_wines` не называются предсказаниями модели; сырой `match_score` показан как балл, не процент |
| Полная карточка | `image_url`, `grapes`, `vintage`, `style`, `tasting_notes`, `food_pairing` | показываются имеющиеся `name`, `winery`, `region`, `description`, `rating` |
| Роскачество | отдельный объект `roskachestvo` с проверенным баллом | «Оценка скоро появится»; обычный `rating` подписан «Народный рейтинг» |
| Заявка на отсутствующее вино | `POST /feedback/wine-submissions`, включая `uploaded_image_id` | форма сохраняет **только черновик** в текущем браузере и сообщает, что он не отправлен |
| Данные этикетки | `ocr_lines` в ответе задачи | новая форма начинается пустой, без автоматической подстановки |
| Участие вина в фестивале | `festival_eligible` и проверенный URL события | приглашение отключено по умолчанию, формулировка не утверждает участие конкретной бутылки |
| Сомелье Григорий | будущий чат/подбор | видимый компонент «Скоро», без имитации работающего диалога |

При каждом новом открытии формы поля, отметка «Я уже пробовал(а)» и оценка должны начинаться пустыми. Сохранённый черновик подставляется **только** по нажатию кнопки «Восстановить черновик»; согласие на отправку не восстанавливается.

## Флаги

- `VITE_FESTIVAL_ENABLED=false`: значение `true` включает приглашение после успешного сканирования, один шанс на задачу/сессию. `VITE_FESTIVAL_CHANCE=0.25` задаёт вероятность от 0 до 1; ссылка задаётся `VITE_FESTIVAL_URL`. URL из ТЗ надо проверить до включения. Участие конкретного вина не утверждается без данных. Демо `wine_6` показывает приглашение независимо от этого флага.
- `VITE_FEEDBACK_ENABLED=false`: включайте **только после реализации** и проверки `POST /feedback/wine-submissions`. Текущая форма не обманывает пользователя сообщением об успешной отправке.
- `VITE_DEMO_MODE=false`: при `true` — локальный просмотр сценариев `wine_1`…`wine_6` без запросов к FastAPI.

## Структура

- `src/pages/`: главный экран, камера, результат.
- `src/components/`: рамка, карточка, варианты, форма, фестиваль, Григорий.
- `src/api/`: запросы FastAPI и будущая заявка.
- `src/hooks/`: жизненный цикл камеры и задачи распознавания.
- `src/lib/image.ts`: вырезка видимой области этикетки.
- `src/types.ts`: контракт API; `src/config.ts`: URL и флаги.
- `src/styles/tokens.css`: централизованная палитра для согласования с бренд-гайдом.
- `src/data/popularWines.ts`: демонстрационная подборка без заявлений о реальной популярности.
- `public/demo/wines.json` и `public/demo/wine_*.webp`: локальные карточки и фотографии для демо; `src/data/demoRecognition.ts` задаёт сценарии по выбранному имени файла.
- `public/brand/`: знак проекта и SVG для footer; `src/assets/grigory.jpg`: аватар анонса сомелье.
